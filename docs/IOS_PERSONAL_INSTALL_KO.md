# 맥북에서 내 아이폰에 지갑의 일기 설치하기

이 문서는 앱스토어 출시 없이 **본인의 맥북과 아이폰에** 개발용 앱을 직접 설치하는 방법입니다. Apple의 무료 Personal Team을 이용합니다. iOS 프로젝트와 아래 절차는 Windows에서 준비했으며, 실제 Mac 빌드 및 iPhone 설치·동작은 아직 검증되지 않았습니다. 오류가 발생할 수 있습니다.

## 먼저 알아둘 점

- 무료 계정의 개발용 앱은 프로비저닝 프로필이 발급 후 7일에 만료되어 다시 빌드하고 설치해야 합니다. 이 방법은 앱스토어에 앱을 게시하지 않습니다.
- 앱을 삭제하거나 번들 식별자(Bundle Identifier)를 바꾸면 기기에 저장된 가계부에 접근하지 못하거나 데이터가 삭제될 수 있습니다. 업데이트·재설치 전에 기기 전체 백업과 앱에서 가능한 가계부 내보내기를 확인하세요. 기기에 처음 설치한 이후에는 같은 Apple 계정과 같은 번들 식별자를 유지하고, 앱을 지우지 않은 채 Xcode에서 다시 실행하세요. 백업·재설치 복원이 모든 상황에서 보장되지는 않습니다.
- iPhone 단축어 입력 연결을 추가했습니다. 메시지/지갑 입력 동작은 iOS 16 이상, 다른 앱의 **알림 자동화는 iOS 27 이상**에서 설정합니다. 사용자가 직접 설정한 자동화가 전달한 내용만 받으며 모든 은행 앱이나 문자함을 직접 읽는 기능은 아닙니다.
- **앱이 닫혀 있으면 단축어 입력은 기기에 대기 저장하고, 가계부·취소 처리·예산 알림은 앱을 열어 처리한 뒤 갱신됩니다.** Android의 알림 감지 서비스와 동일한 즉시 백그라운드 기록은 아닙니다. 앱 강제 종료·재부팅·잠금 상태의 전달은 실기기 검증이 필요합니다.
- PDF 저장은 파일 앱의 저장 위치 선택창, 공유는 iOS 공유창을 사용합니다. 이미지 및 스캔 문서는 기기 내 Vision 문자 인식을 사용하며, 기기에서 지원하지 않는 언어는 오류로 표시합니다. 수동 지출·SQLite 저장·PDF·여행 초대/동기화와 새 네이티브 기능 모두 실제 Mac 빌드/iPhone 동작 검증은 아직 남아 있습니다. 중요한 파일은 파일 앱에서 열어 확인하세요.
- 아래 명령은 처음 내려받는 경우입니다. 이미 지갑의 일기를 개발 중이라면 기존 폴더나 변경사항을 덮어쓰지 말고 별도의 새 폴더에서 시작하세요.

## 준비물

1. iOS 27.2 아이폰과 macOS 27.2 맥북에는 **Xcode 27.2 또는 해당 기기를 지원하는 후속 버전**을 사용하세요. Apple 지원표에서 Xcode 27.2의 macOS 요구사항은 26.6 이상이며 iOS 27.2 SDK가 포함됩니다. 앱의 기본 배포 대상은 iOS 15 이상이지만, 단축어 입력 동작은 iOS 16 이상, 이 안내의 앱 알림 자동화 대상은 iOS 27 이상입니다. 케이블과 인터넷도 필요합니다. 다른 조합은 아래 Apple 공식 Xcode 지원표를 확인하세요.
2. Mac App Store에서 Xcode 설치 후 처음 열어 필수 구성요소 설치와 약관 화면을 완료하세요.
3. Node.js 22.13 이상과 npm. 터미널에서 `node --version`과 `npm --version`으로 확인하세요. Node는 공식 사이트 <https://nodejs.org/>에서 설치할 수 있습니다.
4. 아이폰 소유자의 Apple 계정. 계정 비밀번호, 인증 코드, 서명 파일을 다른 사람이나 채팅에 보내지 마세요. Apple이 개발자 등록 및 약관 동의를 요청하면 기기 소유자가 직접 진행하세요.

## 받은 iOS 소스 ZIP으로 준비 — 이번 업데이트

이번 iOS 변경은 아직 GitHub에 업로드하지 않았습니다. 아래 GitHub 복제 명령만 실행하면 이번 단축어·PDF·문자 인식 구현이 없는 이전 소스를 받을 수 있으니, 전달받은 `Wallet-Diary-v버전-iOS-source.zip`을 사용하세요. ZIP은 **설치용 IPA가 아니라 빌드용 소스**입니다. Android APK/AAB를 iPhone에 설치할 수는 없습니다.

멀리 있는 가족에게는 이 ZIP과 이 안내 문서를 메신저·이메일·본인이 선택한 파일 전달 수단으로 보내면 됩니다. ZIP을 받은 사람이 자신의 맥북에서 빌드하고 자신의 Apple 계정으로 서명합니다. Apple 계정이나 비밀번호를 서로 공유할 필요는 없습니다. ZIP을 아이폰에 복사하는 것만으로 설치되지는 않습니다.

1. 맥북에 ZIP을 다운로드하고 압축을 풉니다. 생성된 `Wallet-Diary-iOS` 폴더를 찾습니다. 기존 작업 폴더에 덮어쓰지 마세요.
2. 터미널에 `cd `를 입력하고 끝에 공백을 둔 다음, Finder의 `Wallet-Diary-iOS` 폴더를 터미널로 끌어다 놓고 Return을 누릅니다.
3. 다음 명령을 한 줄씩 실행합니다.

```bash
npm run ios:check
npx cap open ios
```

`ios:check`가 실패하면 설치로 넘어가지 말고 오류를 확인하세요. 이 ZIP에는 비밀키, Apple 계정, Android 서명 키, 실제 가계부 데이터가 없습니다. `android/app/build.gradle` 파일 하나는 Android/iOS 버전 일치 테스트용으로만 들어 있으며 Android를 빌드할 수 있는 패키지가 아닙니다. Firebase 웹 설정은 기존 앱의 공개 연결 설정이며 서버 관리자 권한이나 비밀 API 키가 아닙니다.

`ios:check`는 `npm ci`를 내부에서 실행하므로 의존성 설치 명령을 먼저 반복할 필요는 없습니다. `Unsigned iOS build passed`까지 표시된 경우에만 다음 Xcode 설치 단계로 진행하세요. `xcodebuild`를 찾지 못하거나 Command Line Tools만 선택되어 있다는 오류가 나오면 Xcode의 **Settings → Locations → Command Line Tools**에서 설치한 Xcode를 선택하고 재시도하세요.

## GitHub에서 준비 — 변경사항이 업로드된 뒤에만

이번 iOS 변경이 GitHub에 반영됐다는 별도 확인을 받은 뒤에만 이 방법을 사용하세요. 맥북에서 터미널을 열어 아래 명령을 한 줄씩 실행합니다. 처음 명령은 현재 위치에 `Together` 폴더를 만듭니다.

```bash
git clone --branch codex/wallet-diary-v1 https://github.com/Seunghyeon-Kim-0920/Together.git
cd Together
npm ci
npm run ios:sync
npx cap open ios
```

`npm run ios:sync`는 웹 화면을 빌드하고 iOS 프로젝트에 복사합니다. 이 단계는 반드시 **맥에서** 실행하세요. GitHub에는 생성된 웹 자산이 들어 있지 않아, 동기화하지 않고 Xcode만 열면 앱이 빌드되지 않거나 제대로 실행되지 않을 수 있습니다. 첫 빌드에는 Swift 패키지 다운로드도 필요합니다. 에러가 나오면 임의로 유료 서비스에 가입하지 말고 오류 문구를 확인하세요.

## 아이폰에 설치

1. 아이폰을 맥북에 연결하고 잠금을 푼 다음, 두 기기에서 신뢰 여부를 묻는 화면이 나오면 확인합니다.
2. Xcode 메뉴 **Settings → Accounts**에서 아이폰 소유자의 Apple 계정으로 로그인합니다. 무료 계정은 `Personal Team`으로 표시됩니다.
3. Xcode 왼쪽에서 `App` 프로젝트 → `App` 타깃 → **Signing & Capabilities**를 엽니다. `Automatically manage signing`을 켜고 본인의 Personal Team을 선택합니다.
4. 번들 식별자 등록 충돌이 나면 Xcode의 Bundle Identifier를 본인만 쓰는 고유한 값으로 바꿉니다. 예를 들면 `com.example.walletdiary`가 아니라 본인에게 고유한 영문 식별자를 사용하세요. 실제 충돌 여부는 계정마다 다릅니다. 최초 설치 후 이 값을 바꾸면 별도 앱으로 취급될 수 있으니 계속 유지하세요.
5. Xcode 상단 실행 대상을 연결한 아이폰으로 선택합니다. 아이폰에서 개발자 모드가 필요하다고 안내하면 **설정 → 개인정보 보호 및 보안 → 개발자 모드**를 켜고, 재시동 후 아이폰에서 직접 확인합니다. 개발자 모드는 기기 보안을 낮추므로 직접 이해하고 동의할 때만 켭니다.
6. Xcode의 ▶ 실행 버튼을 눌러 빌드하고 설치합니다. 아이폰에서 개발자 앱 신뢰를 요청하면 화면의 안내에 따라 확인합니다.

## 단축어로 자동기록 연결

1. 앱에서 생활 가계부를 만들고 **카드·이체 자동기록 → 동의하고 단축어 입력 받기**를 켭니다. 새 은행·카드 입력 검토를 켜고, 문자를 쓰면 문자 입력도 별도로 켭니다.
2. 단축어에서 알림 자동화를 만들고 **실제 은행·카드 앱만** 선택합니다. 앱의 **은행 알림 전달** 동작에 원본 앱 이름, 알림 제목, 알림 본문을 연결합니다. 출처 이름은 변경하지 않고 일정하게 유지하세요. 단축어에 본문을 직접 고정 입력하지 마세요.
3. 문자는 메시지 자동화에서 은행 발신자·본문 조건을 지정한 다음 **은행 문자 전달** 동작에 발신자와 메시지 내용을 연결합니다. 모든 개인 문자나 인증번호를 전달하는 자동화는 만들지 마세요.
4. Apple Pay는 지갑 거래 자동화의 **지갑 거래 전달** 동작에 실제 거래 금액·ISO 화폐 코드(예: KRW/EUR/USD)·사용처를 연결합니다. 입력이 없으면 임의로 추측하지 마세요. Apple Pay에서 제공되는 항목은 실제 기기에서 확인해야 합니다.
5. 자동 실행/잠금 중 실행은 본인이 설정 화면을 확인하고 켭니다. 단축어를 가져오는 것만으로 자동화가 켜졌다고 가정하지 마세요.
6. 처음 받은 거래는 앱을 열어 출처·금액·사용처를 확인합니다. 은행/발신자를 신뢰하면 다음 고신뢰 거래부터 기존 자동기록 로직으로 반영됩니다. 신뢰하지 않은 출처, 다른 화폐, 사용처 누락, 애매한 취소는 검토가 필요합니다.

출처 이름은 실제 은행을 인증하는 증거가 아닙니다. 원문은 외부 서버로 보내지 않고 백업에서 제외된 비공개 대기함에 보관하며, 기록·제외·삭제 후 지웁니다. 검토 중인 입력은 처리할 때까지 남고, 입력 받기를 끄면 미처리 입력도 삭제합니다. 대기함은 1,000건/2MiB로 제한되며 가득 차면 조용히 버리지 않고 단축어에 오류를 표시합니다.

## Mac 빌드 사전 검사

Xcode 설치·초기 실행 및 Node 준비 후 프로젝트 루트에서 실행합니다.

```bash
npm run ios:check
```

이 명령은 의존성 설치, JavaScript 테스트, 코드 검사, 웹 빌드, iOS 동기화, **Swift 대기함 합성 데이터 테스트**, **서명 없는 iOS 컴파일**을 순서대로 수행합니다. Swift 테스트는 별도 임시 폴더만 사용하며 실제 가계부를 열지 않습니다. Apple 계정으로 로그인하거나 기기에 설치하거나 앱을 게시하지 않습니다. 성공해도 설치용 IPA가 생성된 것은 아닙니다. 이어서 위의 Xcode 개인 서명/설치를 진행하세요. 실패하면 원문 오류를 확인하되 계정 비밀번호·서명 키·거래 원문은 공유하지 마세요.

검사 출력의 `Native inbox host checks passed`와 `Unsigned iOS build passed`는 각각 맥의 대기함 테스트와 서명 없는 앱 컴파일 성공을 뜻합니다. **아이폰에서 알림이 전달됐거나 지출이 기록됐다는 결과가 아닙니다.** 아래 실기기 확인은 별도로 해야 합니다.

## 최초 설치 후 확인할 것

실제 재무 자료를 넣기 전에 가상 금액으로만 시험하세요.

1. **저장·분류:** `아이폰 시험`이라는 원화 생활 가계부에 가상 지출을 넣습니다. 생활·공과금·통신비가 별개로 보이는지, 한국어·영어·프랑스어 전환과 월/연 통계가 맞는지 확인합니다. 앱을 완전히 닫았다 다시 열어 날짜·금액·사용처가 남는지 확인합니다.
2. **단축어 동작 발견·입력:** 단축어의 앱 동작에서 은행 알림 전달·은행 문자 전달·지갑 거래 전달이 검색되는지 확인합니다. 별도 시험 단축어에서 출처 이름을 `시험은행`으로 두고 `결제 승인` / `사용처: 예시카페` / `5,000원`을 각각 줄바꿈한 합성 본문을 전달합니다. 최초 입력은 검토에 있어야 합니다. 이 시험 출처만 신뢰하고 다음 합성 거래가 자동 반영되는지 확인합니다. 시험 단축어에만 고정 본문을 사용하고 실제 자동화에는 원본 입력 변수를 연결하세요.
3. **잘못된 지출 제외·다른 화폐:** 시험 출처로 광고·결제 승인 요청·입금 문구를 전달해 지출이나 검토 목록에 생기지 않는지 확인합니다. 같은 출처라도 원화 가계부에 EUR 거래가 오면 원화를 임의 환산하지 않고 검토에 남아야 합니다.
4. **이름 기억:** 합성 거래 내용을 `예시카페`에서 `아침 커피`로 바꿔 저장합니다. 이후 같은 원본 사용처의 별도 거래가 편집한 이름으로 나타나고, 다른 지점·다른 가계부에는 이름 규칙이 전파되지 않는지 확인합니다. 과거 내역은 일괄 변경하지 않습니다.
5. **중복·취소:** 시험 지갑 거래와 시험 은행 알림에 같은 금액·화폐·가까운 시각을 넣어 같은 결제가 하나만 남는지 확인합니다. 명확히 일치하는 취소/환불 입력 뒤 금액이 되돌려지고, 어떤 거래인지 모호한 취소는 자동 삭제하지 않고 검토에 남는지 확인합니다. 실제 결제를 만들거나 취소할 필요 없이 합성 입력으로 시험하세요.
6. **닫힘·잠금·동의 철회:** 앱을 닫은 상태에서 시험 입력을 보내고 앱을 열었을 때 반영되는지 확인합니다. 잠금과 재부팅 뒤에도 따로 시험하되, 실패를 조용히 성공으로 간주하지 마세요. 입력 받기를 끄면 미처리 입력은 없어지고 이미 기록한 지출은 유지되어야 합니다. 다시 켤 때 개인 대화·인증번호를 전달하는 설정이 없는지 확인하세요.
7. **예산 알림:** 시험 가계부에 작은 가상 월 예산을 정하고 합성 지출을 추가해 80%·100% 도달 안내를 확인합니다. 알림 권한 거부/허용도 각각 확인하세요. 단축어 대기함만 채워진 동안에는 가계부와 예산 알림이 갱신되지 않고 앱이 입력을 처리한 뒤 계산됩니다.
8. **여행:** 여행 가계부를 만들고 참가자 추가·제외, 과거 정산 보존/삭제 선택, 지출 이동·분담·정산을 확인합니다. 함께 쓸 계획이면 두 기기에서 초대, 재접속, 동기화와 정산 결과를 별도로 확인합니다. 초대 코드와 개인 금융정보는 공개 채팅에 올리지 마세요.
9. **파일·PDF·문자 인식:** 가상 명세서 PDF/이미지와 앱 내보내기 파일을 가져와 날짜·사용처·금액 검토 결과를 확인합니다. PDF 저장은 파일 앱 위치 선택창으로, 공유는 공유창으로 열려야 합니다. 취소한 작업은 저장 성공으로 표시되면 안 됩니다. 저장하거나 공유한 PDF를 파일 앱 또는 받은 쪽에서 직접 열고 한글·금액·선택 기간을 확인하세요. 문자 인식은 기기에서 선택한 언어를 지원하지 않으면 오류를 표시하며 실제 지원 여부를 확인해야 합니다.

어느 단계든 앱이 열리지 않거나 데이터가 사라지면 실제 가계부를 입력하지 말고, 실패한 항목과 Xcode 오류 메시지 또는 개인정보를 가린 화면을 기록하세요. 시험용 내역이 실제 가계부와 섞이지 않도록 시험 가계부를 별도로 유지하세요.

프로필이 만료되면 같은 맥북, 같은 Apple 계정, 같은 프로젝트와 번들 식별자로 아이폰을 연결해 Xcode에서 다시 ▶ 실행합니다. 소스가 변경되지 않았다면 일반적으로 다시 내려받을 필요는 없습니다. 앱을 삭제하지 마세요. 재설치 전 백업을 확인하세요.
