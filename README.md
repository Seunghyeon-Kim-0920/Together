# 지갑의 일기

여행 정산과 일상 소비를 한 앱에서 관리하는 오프라인 우선 모바일 가계부입니다. 웹사이트 배포 없이 Capacitor 기반 Android/iOS 앱으로 제공됩니다.

## 주요 기능

- 삼성 인터넷의 탭처럼 여러 가계부를 가로로 전환하고 추가·이름 변경·삭제
- 새 가계부를 여행 가계부 또는 일반 가계부로 선택
- 여행 가계부: 여러 현지 화폐, 참가자, 결제자, 균등 N분의1, 통화별 정산, 파일 공유, PDF 내보내기
- 일반 가계부: 식비·교통비 등 카테고리 입력, 전월 대비 증감률, 월별·연도별·카테고리별 통계
- 생활 지출 → 여행 가계부 이동: 원래 금액·화폐·날짜 유지, 결제자와 분담 참가자 선택, 한 번에 저장하며 원본 재가져오기 중복 방지
- 동행 여행 가계부 합치기: 일반 PDF로 공유하고 첨부 원본 데이터로 참가자·결제자·분담 금액 복원, 합치기 전 중복·수정 충돌과 정산 확인
- 여행·일반 가계부 PDF 저장: 전체 기간 소비내역을 Android 저장 위치 선택창으로 기기에 저장하며 공유창을 열지 않음
- 소비내역 가져오기: PDF, XLSX/XLS/ODS, CSV/TSV, OFX/QIF, JSON, 텍스트/HTML/DOCX/ODT, Android 이미지·스캔 PDF를 읽고 날짜·금액·사용처·카테고리 수정 후 선택 등록
- Android 알림 자동기록: 권한 허용 뒤 새로 게시된 카드 결제, 완료된 보낸 계좌이체, 실제 출금된 자동이체·정기이체를 구분해 기록하고 받은 이체·잔액·예정·실패 및 명시된 본인 계좌 간 이체 알림은 제외
- 은행·카드·결제 앱만 감지: 자동 감지는 은행·카드·간편결제 앱(구글 월렛, 삼성페이, Revolut, Swile, 국내외 은행·카드 앱 등)으로 확인된 알림만 읽습니다. 카카오톡·인스타그램·메일·브라우저·기본 문자 앱은 물론 쇼핑·배달 등 그 밖의 앱 알림은 본문을 읽지 않고 건너뜁니다.
- 자동으로 잡히지 않는 은행 앱 등록: 건너뛴 앱도 이름과 확인 시각만 `최근 앱별 알림 확인`에 남으며, 거기서 직접 결제 앱으로 등록하면 그때부터 검사합니다. 등록한 앱의 첫 후보는 앱 등록과 지출 기록을 각각 확인해야 하며, 모든 언어·알림 형식의 인식을 보장하지 않습니다.
- 현재 알림 다시 확인: 앱 복귀·감지 서비스 재연결·설정 변경 시 알림창에 남아 있는 항목을 재검사하고, 처리한 동일 항목의 재등장을 방지합니다. 수동 다시 확인은 실제 수집 완료까지 기다립니다.
- Swile 등 간결한 사용처+금액, 확장 본문·추가 줄, 마이너스 결제금액도 검사합니다. 미등록 앱과 모호한 형식은 확인 목록으로 보내며 잔액·입금·예정·실패는 제외합니다.
- 최근 앱별 알림 확인: 원문·금액 없이 앱 이름·확인 시각·결제 후보 여부만 기기에 보여줍니다. 앱 감지 해제 시 범위 밖의 미처리 후보도 제거합니다.
- 미연결 Open Banking 개발 기반: 확정 출금 검증, 안정 거래 ID 중복 방지, 내부이체 검토와 취소 후보 생성까지 구현했지만 공급자·백엔드·동의 화면과 아직 연결되지 않음
- 한국어·영어·프랑스어
- 로그인 없이 SQLite에 기기 내부 저장
- 첫 실행 시 예시 사람이나 지출이 없는 완전한 빈 상태

## 개발

```bash
npm ci
npm run dev
npm run lint
npm run typecheck
npm test
npm run build
```

Android 동기화:

```bash
npm run android:sync
```

이 PC에서는 전역 Java/SDK가 아니라 `%LOCALAPPDATA%\TogetherToolchain`의 JDK 21과 Android SDK 36을 사용합니다. 따라서 `where java`가 비어 있어도 아래 스크립트로 로컬 빌드할 수 있습니다. OneDrive/한글 경로 문제를 피하도록 `%LOCALAPPDATA%\TogetherBuild`에 소스를 복사하며 기존 서명 키를 유지합니다.

```powershell
pwsh -File scripts/build-android.ps1
# 빌드가 출력한 정확한 디렉터리를 사용하세요.
pwsh -File scripts/verify-android.ps1 -BuildDirectory '<출력된 BuildDirectory>'
```

검증 스크립트가 소스 일치, 네이티브 테스트, 서명 인증서, 버전, APK 내부 웹 자산, 16 KB 정렬과 AAB 구조를 확인한 다음에만 `release`에 파일을 복사합니다. JDK/SDK가 다른 위치에 있으면 빌드 스크립트의 `-JavaHome`, `-AndroidSdk`를 지정하세요.

Android 알림 인식 코드를 바꿀 때는 JVM 테스트만으로 확인을 끝내지 마세요. release Java 클래스 컴파일 후 [native ICU 정규식 검사](scripts/NOTIFICATION-REGEX-CHECK.md)를 실행하고 실제 기기에서 감지 서비스 연결을 확인해야 합니다. 디자인 기준은 [v1.6.0 디자인 문서](design/v1.6.0/DESIGN.md), 최종 검증 범위는 [릴리스 기록](release/README.md)에 있습니다.

iOS 동기화는 macOS와 Xcode가 필요합니다.

```bash
npm run ios:sync
```

## 데이터와 공유

앱 데이터는 Android/iOS의 기기 내부 저장소(SQLite와 비공개 앱 설정)에 저장됩니다. `동행에게 PDF 보내기`는 `.pdf` 파일을 `application/pdf` 형식으로 공유합니다. PDF는 일반 뷰어에서 읽을 수 있으며 재가져오기용 `wallet-diary.json` 원본을 표준 첨부파일로 포함합니다. 본인 선택·알림 신뢰 앱·예산·자동기록 식별자는 공유하지 않습니다. 받은 PDF를 기기에 저장한 뒤 상단 가져오기에서 선택하고, 참가자·추가·중복·충돌 내역과 정산을 확인한 다음 기존 여행에 합치거나 새 여행으로 저장합니다. 이전 `.walletdiary`/JSON 파일도 계속 읽습니다.

외부 명세서는 확장자 제한 없이 선택하되 실제 읽을 수 있는 형식을 검사합니다. PDF 표는 글자 위치와 열 제목을 함께 읽어 날짜·사용처·출금·입금·잔액 열을 구분합니다. 금액 방식·날짜 순서·열 매핑·텍스트 인코딩을 선택하고 인식 결과를 편집할 수 있습니다. 이미 있는 기록과 원본 ID는 재등록하지 않습니다. 서로 다른 화폐는 환산하지 않고 화폐별 새 일반 가계부 또는 지정한 여행에 저장합니다. 같은 파일에서 명확히 대응되는 환불은 차감하고, 저장된 일반 가계부 지출의 후속 환불은 대상·기존 금액·변경 금액을 확인한 뒤 선택 적용합니다. 전액 환불되어 지출이 없는 경우도 사용자 확인 후 로컬 확인기록을 저장하여 같은 원본의 재등록을 막습니다. 대응이 모호하거나 여행으로 이동한 결제는 직접 대조해야 합니다.

Google Wallet/Samsung Pay와 카드사 알림은 금액·화폐·정규화한 사용처·수신 시각과 앱 종류를 비교하여 한 결제의 알림 쌍을 중복 기록하지 않습니다. 확실히 구분할 수 없는 지연·반복 결제는 확인 목록에서 사용자가 별도 결제인지 결정합니다. 알림에 은행의 공통 거래 ID가 없는 경우 추론이 필요하므로 모든 형식의 무오류를 보장하지 않습니다. 과거에 이미 저장된 중복은 증거 없이 일괄 삭제하지 않습니다.

파일은 기기에서 처리하며 외부 서버로 보내지 않습니다. Android 이미지 인식은 기기에 포함된 ML Kit의 라틴·한국어·중국어·일본어·데바나가리 모델을 사용합니다. 모든 은행 서식·언어·암호화 방식이나 임의의 파일 형식의 인식을 보장하지 않습니다. 사진·스캔은 원본 대조가 필요합니다. 최대 40 MB, 외부 PDF 100페이지, 읽기 20,000행이며 가계부별 저장 한도는 5,000건입니다. 앱 PDF 원본 첨부는 2 MB 제한 초과 시 오류를 표시하고 불완전한 백업을 만들지 않습니다.

앱을 삭제하면 로컬 데이터가 사라질 수 있으므로 중요한 여행 가계부는 `.walletdiary` 파일 또는 PDF로 백업해야 합니다.

## 배포

- Android/iOS application ID: `com.seunghyeonkim.walletdiary`
- Android version: `1.7.2` / code `122`
- Android min SDK: 24, target SDK: 36
- iOS 프로젝트: `ios/App/App.xcodeproj`
- Android APK/AAB: `release/`

서명 키와 비밀번호는 Git에서 제외됩니다. `release/wallet-diary-upload.jks`와 `release/SIGNING-CREDENTIALS.txt`를 안전한 별도 장소에 함께 백업해야 합니다.

서명된 IPA 생성에는 macOS, Xcode, Apple Developer Team, 배포 인증서와 App Store 프로비저닝 프로파일이 필요합니다.

알림이 전혀 없는 거래를 자동 동기화하려면 사용자가 동의하는 공식 Open Banking 공급자와 보안 백엔드가 필요합니다. 이 연결은 v1.7.2에서도 활성화하지 않았으며 공급자 비밀키는 APK에 넣지 않습니다. 앱에 미연결 상태와 명세서 가져오기를 표시합니다. 파일 가져오기는 은행 자동 동기화가 아닙니다. 설계와 출시 수용 기준은 [`docs/OPEN_BANKING_SETUP.md`](docs/OPEN_BANKING_SETUP.md)에 정리되어 있습니다.

월 한도는 저장된 현재 월 지출 기준입니다. 앱이 완전히 닫혀 있는 동안 들어온 미확인 알림을 즉시 지출/예산으로 확정하는 기능은 없으며, 앱 실행·복귀 후 확정 내역으로 갱신합니다. 실제 기기의 서비스 연결·재부팅·절전·공유 앱 전달과 Play Console 사전 출시 검사는 별도로 필요합니다. 서명 빌드 성공은 스토어 승인이나 모든 휴대폰에서의 실행 보장이 아닙니다.
